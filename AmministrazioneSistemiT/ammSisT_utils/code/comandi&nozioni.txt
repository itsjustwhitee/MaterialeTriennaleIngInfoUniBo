- /dev/null	--> ogni read restituisce EOF, ogni write viene scartata
- /dev/random	--> produce byte casuali (realmente), ma BLOCCANTE se non sufficienti a disposizione
- /dev/urandom	--> produce stream pseudo illimitato

POSIZIONALI
- $0		--> Nome dello script o del comando invocato
- $1, $2, …	--> Argomenti posizionali passati allo script o alla funzione
- $#		--> Numero totale di argomenti posizionali
- $@		--> Tutti gli argomenti posizionali, come array, mantenendo le virgolette. Espansione di "$@": "arg1" "arg2" "arg3" ...
- $*		--> Tutti gli argomenti posizionali, come stringa unica. Espansione di "$*": "arg1 arg2 arg3" (tutto in una stringa)

- $$		--> PID (process ID) della shell corrente
- $!		--> PID dell’ultimo comando eseguito in background
- $-		--> Opzioni attive della shell (set) come stringa (es: himBH)
- $_		-->	Ultimo argomento dell’ultimo comando eseguito oppure valore dell’ultima espansione
- $IFS		--> Internal Field Separator – default: spazio, tab, newline (usato per split)



🟠 MECCANISMI UTILI 🟠
- PROCESS SUBSTITUTION
	Permette di usare l'output di un comando come se fosse un file (sarà una named pipe). Molto utile, più veloce e meno macchinoso nel caso di comandi che necessitano di input da file e 
	tale input deve essere generato da un comando (si evitano file temporanei).
	--> <(COMANDO) crea un file leggibile che contiene l'output di COMANDO. COMANDO è lanciato concorrentemente al comando verso cui si fa process substituition
	--> >(COMANDO) crea un file scrivibile e invia il contenuto a COMANDO.
	Queste espressioni vengono espanse in nomi di file speciali.
	
- COMMAND SUBSTITUITION
	Permette di utilizzare direttamente un processo per generare parametri da collocare sulla command line per un altro comando. 
	Prevede due sintassi:
	--> `COMANDO` <-- Obsoleta
	--> $(COMANDO) <-- Preferita
	Le due forme sono equivalenti (a meno di dettagli di alcuni caratteri speciali). COMANDO viene eseguito in una subshell ed il suo output viene sostituito al posto del token.

- BRACE EXPANSION
	meccanismo di espansione per generare sequenze di stringhe secondo un pattern con la stessa sintassi della pathname expansion, ma le stringhe sono generate indipendentemente dal fatto che esistano
	o meno file che rispettano il pattern.
	Sintassi:
	--> [PRE]{EL1,EL2,EL3}[POST]  <-- esempio a{b,c,d}e verrà espnaso in abe ace ade
	--> [PRE]{START...END[...INCR]}[POST] <-- esempio file{9..13..2}.c verrà espanso in file9.c file11.c file13.c. 
											START può essere zero-padding (tipo 009), esempio doc{009..11} → doc009 doc010 doc011
											Se si usano caratteri per START e END si ha un "prodotto cartesiano", ad esempio {a..c}{1,3} → a1 a3 b1 b3 c1 c3
											Nota: INCR si può usare anche con le lettere (segue ordine alfabetico)
	Più brace expression si possono scrivere innestate (nesting).

- VALORI DEFAULT
	Utile per assegnare valori di default in un assegnamento.
	--> ${VAR:-"default"}	<-- usa la stringa "default" se la variabile VAR è null o not set (non altera VAR).
	--> ${VAR:=default}		<-- usa default se VAR è null o not set e poi in ogni caso espansa, assegna a VAR
	--> ${VAR:?"default"}	<-- stampa su stderr "default" ed esce se VAR null o not set.
								Nota: omettendo il “:”, la stringa vuota viene considerata valida ed il valore di default è usato solo se la variabile fornita è not set

- MANIPOLAZIONE VARIABILI / SEARCH & REPLACE
	--> ${#name}				<-- Lunghezza della stringa
	--> ${name#pattern}			<-- Rimuove la parte più breve all'inizio che corrisponde a pattern
	--> ${name##pattern}		<-- Rimuove la parte più lunga all'inizio che corrisponde a pattern
	--> ${name%pattern}			<-- Rimuove la parte più breve alla fine che corrisponde a pattern
	--> ${name%%pattern}		<-- Rimuove la parte più lunga alla fine che corrisponde a pattern
	--> ${name/pattern/string}	<-- Sostituisce la prima occorrenza di pattern con string
	--> ${name//pattern/string}	<-- Sostituisce tutte le occorrenze di pattern con string
	Altri usi in man bash.1

- ARITHMETIC EVALUATION
	(( )) si comporta come "" nel proteggere gli elementi dell'espressione. 
	Riconosce le variabili per nome:
		• anche se non sono dichiarate intere
		• senza bisogno dell’espansione bash (quindi senza prefisso $)
			– attenzione: l’espansione è ammessa ma in tal caso non vale quanto segue:
		• interpretandole a valore zero se non definite
	Il toke $(( )) viene espanso col risultato dell'espressione.
	Operatori:
		--> id++ id-- (post-incremento/decremento)
		--> ++id --id (pre-incremento/decremento)
		--> + - * / somma sottrazione prodotto divisione
		--> ** % elevamento a potenza, modulo   (Nota: ** è supportato solo in Bash, non in tutte le shell POSIX)
		--> ! ~ & | ^ NOT NOT AND OR XOR bit-a-bit
		--> << >> shift binario a sinistra / destra
		--> = *= /= %= += -= <<= >>= &= ^= |= assegnamento
		--> <= >= < > == != confronto
		--> && || AND / OR logico
		--> expr1?expr2:expr3 (solo in contesti aritmetici Bash, non standard in tutte le shell) restituisce il risultato di expr2 o expr3 rispettivamente se expr1 è true o false
	I numeri possono essere espressi in qualsiasi base tra 2 e 64:
		– default 10, prefisso 0 → ottale, prefisso 0x → esadecimale
		– prefisso B# → base B
			• cifre utilizzabili: 0..9a..zA..Z@_
			• per B<=36, a..z e A..Z sono intercambiabili
	
- FUNZIONI
	Le funzioni sono sequenze di comandi con un nome
	--> function NOME() { SEQUENZA ; }
	Possono ricevere parametri
		– utilizzabili come i parametri posizionali dello script $1, $2, ...
			• che divengono inaccessibili
			• solo $0 resta impostato al nome script
		– il nome della funzione viene posto in $FUNCNAME

- ARRAY
	Si dichiarano con declare -a ARRAY 
	Accesso:
	--> "${arr[@]}"	<--	Tutti gli elementi, uno per uno (rispetta spazi), esempio "uno" "due" "tre con spazi"
	--> "${arr[*]}"	<--	Tutti gli elementi, come un’unica stringa separata da $IFS, esempio "uno due tre con spazi"
	--> ${arr[@]}	<--	Tutti gli elementi, word splitting attivo, esempio 'uno' 'due' 'tre' 'con' 'spazi' (parole divise, le virgolette sono a scopo illustrativo)
	--> ${arr[*]}	<--	Idem, ma trattati come un’unica parola, esempio 'uno due tre con spazi' (unica parola, le virgolette sono a scopo illustrativo)
	--> ${#arr[@]}	<--	Numero di elementi, esempio con l'array di sopra sarebbe 3
	--> ${#arr[i]}	<--	Lunghezza dell'elemento i, esempio con i=3 dell'esempio sopra sarebbe 13
	--> ${!arr[@]}	<--	Lista degli indici, esempio 1 2 3
	Si possono definire anche array associativi con declare -A ARRAY, quindi array con stringhe come chiavi (non indici numerici). Funzionano come sopra.
	Tip per usare nomi a tempo di esecuzione: eval

- CRONTAB (FILE)
	Struttura di una riga di un file crontab:
	MINUTO ORA G.MESE MESE G.SETTIMANA <COMANDO>
	--> COMANDO é eseguito quando l'ora corrente corrisponde a tutti i selkettori di una riga (campi in AND logico)
		Eccezione: se sono specificati sia giorni della settimana che giorni del mese (settati quindi non *), i due sono considerati in OR (esempio: G.MESE=1,12 e G.SETTIMANA=2 => ogni giorno 1 e 12 del mese + ogni martedí)
		I campi possono contenerre:
		- range: NUMA-NUMB oppure *		--> range di valori, * = tutti
		- liste: NUMA,NUMB[,...] 		--> elenco di numeri
		- step: RANGE/NUM 				--> dimensione del "passo" (esempio ORA=6-12/3 => ogni 3 ore tra le 6 e le 12, quindi 6 9 12) 
	
🟣 ESPANSIONE 🟣
	1. Brace expansion ({a,b})
	2. Tilde expansion
	3. Espansione di parametri e variabili ($VAR, ${VAR}, $((...)), $(...))
	4. Espansione di command substitution
	5. Arithmetic expansion ($((...)))
	6. Espansione di process substitution (<(...), >(...))
	7. Rimozione quoting (' ' e " ", dopo che le espansioni sono avvenute)
	8. Espansione di word splitting (se non protetto da virgolette, l'output è diviso in parole da spazi, tab, newline)
	9. Pathname expansion (*, ? e [])
	10. Assegnazione di comandi (variabili in linea prima del comando sono valide solo per quel comando)
	11. Espansione ridirezione (>, <, >>, 2>, ...) e i file vengono aperti
	12. esecuzione del comando

	1. Tokenizzazione: la riga è divisa in token, usando come separatori un elenco di metacaratteri:
		SPACE TAB NEWLINE ; ( ) < > | &
		I token possono essere:
			- stringhe
			- parole chiave
			- caratteri di ridirezione
			- carattere ':'
		Da qui in poi (2-10) tutti i passi sono saltati per le parti di riga racchiuse tra apici singoli ''.
	2. primo token = alias?
		La shell cerca il primo token nella lista degli alias. Se lo trova lo espande e riparte con i processing da 1.
		Nota: questo consente alias ricorsivi, ma questo non permette di espandere un alias due volte.
		Non si esegue per le parti racchiuse da apicidoppi "".
	3. primo token = keyword?: se il primo token è una parola chiave che dà inizio a un comando composto (i.e. if, while, function (, {) la shell predispone l'ambiente per il comando composto e ne va a leggere il primo token.
		Non si esegue per le parti racchiuse da apicidoppi "".
	4. Brace expansion
		Non si esegue per le parti racchiuse da apicidoppi "".
	5. Tilde expansion: se ci sono toke nella forma ~username vengono sostituite con la home directory di username (se username è vuoto si usa utente corrente).
		Non si esegue per le parti racchiuse da apicidoppi "".
	6. Parameter expansion: il carattere '$' può marcare l'inizio di diverse espansioni (parameter expansion, command substitution, arithmetic expansion), la PE è la più semplice
	7. Command substitution: il token $(comando) ha questo effetto:
			– viene creata una subshell
			– vi viene eseguito comando
			– sdtout di comando viene posto sulla riga di comando al posto del token originale, a parte eventuali righe vuote alla fine
	8. Arithmetic expansion: il token ((expr)) causa la valutazione di expr, un’espressione aritmetica. Se preceduto da $, il risultato viene posto sulla riga di comando, altrimenti l’unico effetto è eventualmente sulle variabili
		expr viene trattata come se fosse racchiusa tra doppi apici (quindi subisce solo i passi 6 e 7).
	9. Process substitution: il token <(comando) o >(comando) ha questo effetto:
			– comando viene eseguito in modo concorrente e asincrono rispetto al resto della riga
			– il suo input o output appare come un "nome di file" tra gli argomenti del comando
	10. Word splitting: I risultati dei passi 6..9 sono esaminati e separati in parole indipendenti.
		– Separatore = qualsiasi carattere presente nella variabile IFS (default: spazio, tab, newline).
		Non eseguito sulle parti di riga racchiuse tra doppi apici "".
	11. Pathname expansion (espansione dei nomi di percorso)
		Ogni parola viene esaminata e, se contiene uno dei caratteri:
			- *
			- ?
			- [
		viene considerata un pattern e sostituita con tutti i nomi di file che corrispondono nel filesystem.
		Non eseguito sulle parti di riga racchiuse tra doppi apici "".
	12. Quote removal ed esecuzione del comando
		Vengono rimosse tutte le occorrenze di caratteri di quoting effettivamente usate:
			- non protette da altri quoting
			- non generate dai passi 6..9
		Vengono impostati gli stream in caso di redirezione.
		Il comando viene cercato in quest’ordine:
			- funzioni
			- builtin
			- eseguibili in $PATH

Quoting: 
\ (backslash)		--> Protegge il carattere immediatamente successivo, impedendone l'interpretazione speciale.
' (apice singolo)	--> Tutti i caratteri racchiusi tra apici singoli vengono trattati letteralmente, senza alcuna espansione.
" (apice doppio)	--> I caratteri racchiusi tra virgolette doppie sono protetti dall'espansione, tranne per $, backtick (`), \ e alcuni altri casi particolari.

I simboli di quoting, essendo caratteri speciali, devono essere protetti dall'espansione se si desidera utilizzarli con il loro valore letterale. Esempi:
	- \"  : il backslash protegge le virgolette doppie → sulla riga resta "
	- '"' : gli apici singoli proteggono le virgolette doppie
	- \\  : il primo backslash protegge il secondo → sulla riga resta \
	
	
🟤 VARIE 🟤
- $ COMANDO > FILE 2>&1	--> la shell applica da sinistra a destra le ridirezioni, quindi prima stdout è ridiretto su FILE e poi stderr su stdout (quindi FILE)
- $ COMANDO <<MARCATORE	--> Here documents: invia un testo (più righe) a COMANDO e si interrompe quando arriva a MARCATORE (se MARCATORE contiene spazi chiuderlo tra ''). Se si aggiunge - prima di MARCATORE, vengono ignorate tabulazioni (non spazi).
- $ COMANDO <<< "testo da mandare a stdin di COMANDO" --> Here string: si può mandare a stdin del comando una singola riga senza MARCATORE
- $ exec NUM>DEST 	--> Ridirezione definitiva del canale NUM su DEST (esempio $ exec 2>/dev/null). Per ripristinare $ exec NUM>&-
- $ exec NUM< FILE_IN 	--> creazione di nuovo fd (NUM) che legge da FILE_IN. Per leggere <&NUM e per chiudere NUM>&-
- $ exec NUM> FILE_OUT	--> creazione di nuovo fd (NUM) per output su FILE_OUT. Per scrivere >&NUM e per chiudere NUM>&-
- $ exec NUM<> FILE_IO	--> creazopme di nuovo fd (NUM) per output e input su/da FILE_IO. Per chiudere NUM>&-
- ( COMANDO1 ; COMANDO2 ; ...) --> forza la creazione di una subshell in cui eseguire i COMANDO. I/O sono collegati alla shell padre (=> si può usare anche per pipe)
- segnali nel terminale:
	- SIGSTP	--> CTRL + Z
	- SIGINT	--> CTRL + C
	- SIGQUIT	--> CTRL + \
- COMANDO & --> per eseguire COMANDO in backgroun, è restituito un job_id che identifica il processo nella shell. Il pid del processo è memorizzato in $!


🟢 COMANI UTILI (breve excursus, fare riferimento al man) 🟢

$ man COMANDO
--> per ottenere il manuale di COMANDO. Se COMANDO è builtin allora non esiste man page dedicata, tipicamente sono in $ man bash.1

$ help COMANDO_BUILTIN
--> per ottenere info su COMANDO_BUILTIN (non ha man).

$ whoami 
--> indica il proprio username

$ id
--> dà informazioni sull'identità e sul gruppo di appartenenza

$ who
--> indica chi e' attualmente collegato alla macchina

$ type -a COMANDO
--> restituisce tipo di comando (builtin, command, alias) e i path in cui si trova (-a)

$ \COMANDO
--> usa il comando builtin, se COMANDO è un alias. Se COMANDO è una funzione, esegue la funzione.

$ builtin COMANDO
--> usa il comando builtin invece di alias o funzione se COMANDO è stato ridefinito (override).

$ commando COMANDO
--> usa il comando esterno (non per builtin) invece di alias o funzione se COMANDO è stato ridefinito, invocando la versione originale.

$ alias ALIAS_COMANDO='NUOVO_COMANDO'
--> per assegnare all'alias ALIAS_COMANDO l'esecuzione di NUOVO_COMANDO.

$ unalias ALIAS_COMANDO
--> per rimuovere l'alias.

$ wich COMANDO
--> per riconoscere quale comando si sta usando (utile nel caso in cui siano presenti più omonimi)

$ history
--> per ottenere l'elenco dei comandi passati

$ script
--> permette di catturare in un file una sessione di lavoro (in pratica i comandi lanciati ed i corrispondenti output). Per terminare la sessione CTRL+d oppure $ exit

$ cat [OPZIONI] FILE1 [FILE2 FILE3 ...]
--> filtro. Mostra su stdout il contenuto del file (se non vengono passati argomenti mostra quanto scritto sul prompt)

$ tac [OPZIONI] FILE1 [FILE2 FILE3 ...]
--> filtro. Come cat (v. sopra) ma righe in ordine inverso (dall'ultima alla prima).

$ less [OPZIONI] FILE1 [FILE2 ...]
--> Mostra il contenuto del file per videate succssive navigabili. 
    Comandi utili (non sono opzioni):
	– h 		--> help (dei comandi disponibili)
	– frecce/pag–su/giu movimento
	– F 		--> Follow; scorre fino al termine dell’input e resta in attesa che compaiano nuove righe da mostrare
	– <N>g 		--> si porta alla riga numero <N> (default: 1)
	– G 		--> si porta al termine del file
	– /<pattern> 	--> cerca la riga successiva al cursore contenente <pattern>
	– ?<pattern> 	--> cerca la riga precedente il cursore contenente <pattern>
	– n 		--> ripete la ricerca fatta in precedenza
	– N 		--> ripete la ricerca fatta in precedenza, ma nel verso opposto
	– q 		--> esce da less

$ rev [OPZIONI]
--> filtro. Permette di invertire l'ordine dei caratteri di ogni linea (conservando l'ordine delle righe) dello stream in input verso lo stream di output.

$ head [OPZIONI] [FILE1 ...]
--> filtro. Permette di estrarre la parte iniziale di un file. Default prime 10 righe.
    Opzioni utili:
	-c [-]NUM 	--> produce i primi NUM caratteri. Con -NUM produce tutto il testo eccetto gli ultimi NUM caratteri.
	-n [-]NUM 	--> produce le prime NUM righe. Con -NUM produce tutto il testo eccetto le ultime NUM righe.

$ tail [OPZIONI] [FILE1 ...]
--> filtro. Permette di estrarre la parte finale di un file. Deafault ultime 10 righe.
    Opzioni utili:
    	-c [+]NUM 	--> produce gli ultimi NUM caratteri. Con +NUM produce tutto il testo eccetto i (a partire dai) primi NUM caratteri.
    	-n [+]NUM 	--> produce le ultime NUM righe. Con +NUM produce tutto il file eccetto le (a partire dalle) prime NUM righe.
    	-f 		--> dopo aver mostrato le ultime righe di un file, mantiene il file aprto e si visualizzano in tempo reale eventuali nuove righe appese da altri processi (ignora quindi EOF).
    			    Si possono aggiungere (a -f):
    			    	--pid=PID 	--> per far terminare il tail quando termina il processo con pid PID.
    			    	--retry		--> per far riprovare ad aprire il file finchè non si riesce (utile se è necessario aspettare che un altro processo generi il file).

$ cut [OPZIONI] [FILE1 ...]
--> filtro. Permette di tagliare parti di righe.
    Opzioni utili:
    	-c ELENCO	--> permette di returnare uno o più caratteri. 
    				     ELENCO può assumere diverse forme:
    					NUMA 		--> carattere in posizione NUMA.
    					NUMA-NUMB 	--> caratteri in posizione da NUMA a NUMB (compresi). 
    				    	NUMA-		--> caratteri dalla posizione NUMA (compreso) in poi.
    				    	-NUMB		--> caratteri fino alla posizione NUMB (compreso).
	-d CHAR -f ELENCO [-s]	--> permette di spezzare ogni riga in campi delimitati dal carattere CHAR e selezionare solo quelli specificati in ELENCO (v. opzione sopra -c). 
				    Se specificato -s evita che vengano prodotte in output righe che non contengolo il delimitatore CHAR.
				    
$ sort [OPZIONI] [FILE1 ...]
--> filtro. Permette di ordinare in modo lessicale. L'ordine segue il valore dei byte che codificano i caratteri se LC_ALL=C, altrimenti l'ordine del locale.
    Opzioni utili:
    	–u	--> elimina le entry multiple (equivale a sort | uniq)
	–r	--> reverse (ordinamento decrescente)
	–R	--> random (permutazione casuale delle righe)
	–m	--> merge di file già ordinato
	–c	--> controlla se il file è già ordinato
	-b	--> ignora gli spazi a inizio riga
	-d	--> considera solo i caratteri alfanumerici e gli spazi
	-f	--> ignora la differenza minuscole / maiuscole
	-n	--> interpreta le stringhe di numeri per il valore numerico
	-h	--> interpreta i numeri “leggibili” come 2K, 1G, ecc.
	-t SEP	--> imposta SEP come separatore tra campi (default: spazi)
	-k KEY	--> chiave di ordinamento – se usato più volte, ordina per la prima chiave, a parità di questa per la seconda, …
		    KEY è nella forma (semplificata) F[.C][,F[.C]][OPTS]
			• F = numero di campo
			• C = posizione (in caratteri) nel campo
			• OPTS = una delle opzioni di ordinamento [bgiMhnRrV]

$ uniq [OPZIONI] [FILE1 ...]
--> filtro. Permette di eliminare i duplicati consecutivi.
    Opzioni utili:
    	–c	--> indica anche il numero di righe compattate in una.
	–d	--> mostra solo le entry non singole.
	
$ wc [OPZIONI] [FILE1 ...]
--> filtro. Conteggia caratteri, righe e/o parole,
    Opzioni utili:
    	-c 	--> conta i caratteri.
	-l 	--> conta le linee.
	-w 	--> conta le parole (stringhe separate da spazi).

$ grep [OPZIONI] [FILE1 ...]
--> filtro. Esamina le righe del testo in ingresso. Riproduce in uscita quelle che contengono un pattern corrispondente a una espressione regolare passata come argomento.
    Regex (solo opzione -E o egrep):
    	– RE = uno o più rami non vuoti separati da |
	– ramo = uno o più pezzi concatenati tra loro
	– pezzo = atomo eventualmente seguito da un moltiplicatore
	– atomo = uno di:
		• (RE)
		• [charset]
			Esempi
				[abc] indica UN qualsiasi carattere fra a, b o c.
				[a-z] indica UN qualsiasi carattere fra a e z compresi.
				[^dc] indica UN qualsiasi carattere che non sia né d né c.
			[:NOME_CLASSE:] charset basati su character class, NOME_CLASSE deve appartenere ad un insieme definito (wctype 3):
				alnum, digit, punct, alpha, graph, space, blank, lower, upper, cntrl, print, xdigit.
			Un set può essere negato con ! o ^ (tipo [!a] o [^A->])
		• Atomi speciali:
			. indica UN qualsiasi carattere.
			^ indica l'inizio della linea.
			$ indica la fine della linea.
		• backslash sequence
			\< – \> la stringa vuota all’inizio – alla fine di una parola.
			\b la stringa vuota al confine di una parola.
			\B la stringa vuota a condizione che non sia al confine di una parola.
			\w è sinonimo di “una qualsiasi lettera, numero o _”.
			\W è un sinonimo “un qualsiasi carattere non compreso in \w”.
		• Singolo carattere
	   Per atomo:		
		> Moltiplicatori (vanno postposti all'atomo, tipo [a-zA-Z]{2,} ovvero "sequenza di almeno due lettere maiuscole o minuscole):
			{n,m} indica da n a m occorrenze dell’atomo che lo precede.
			? indica zero o una occorrenza dell’atomo che lo precede.
			* indica zero o più occorrenze dell’atomo che lo precede.
			+ indica una o più occorrenze dell’atomo che lo precede.
	Greediness:
		– Nel caso in cui una RE possa corrispondere a più di una sottostringa di una data stringa, la RE corrisponde a quella che inizia per prima nella stringa.
		– Se a partire da quel punto, la RE può corrispondere a più di una sottostringa.
	Opzioni utili:
		-E 	--> usa le extended RE (come egrep senza parametri).
		-F 	--> disattiva le RE e usa il parametro come stringa letterale.
		-w/-x 	--> fa match solo con RE “whole word” o “whole line”.
		-i 	--> rende l’espressione insensibile a maiuscole e minuscole.
		-r 	--> cerca ricorsivamente in tutti i file di una cartella.
		-f 	--> FILE prende le RE da un FILE invece che come parametro.
		-o 	--> restituisce solo le sottostringhe che corrispondono alla RE invece della riga che le contiene, separatamente una per riga di output.
		-v 	--> restituisce le linee che non contengono l’espressione.
		-l 	--> utile passando a grep più file su cui cercare: restituisce solo i nomi dei file in cui l’espressione è stata trovata.
		-n 	--> restituisce anche il numero della riga contenente l’espressione.
		-c 	--> restituisce solo il conteggio delle righe che contengono la RE.
		--line-buffered --> disattiva il buffering.

$ tar [OPZ] [ARGS]
--> permette di creare archivi.
	Va sempre specificato uno (SOLO) dei seguenti comandi:
		-A			--> concatena più archivi
		-c			--> crea un nuovo archivio
		-d			--> trova le differenze tra archivio e filesystem
		-r			--> aggiunge file ad un archivio
		-t			--> elenca il contenuto di un archivio
		-u			--> aggiorna file in un archivio
		-x			--> estrae file da un archivio
		--delete	--> cancella file da un archivio
	Altre opzioni (facoltative) sono:
	-f FILENAME		--> per specificare un file di archiviazione (altrimenti assume /dev/tape per ragioni storiche). FILENAME puó essere - (carattere '-') quando si specificano le opzioni:
							-d (differenze/confronto): Confronta l'archivio con i file sul filesystem.
							-t (list): Elenca il contenuto dell'archivio.
							-x (extract): Estrae i file dall'archivio.
							-c (create): Crea un nuovo archivio. Quindi usa - per creare l'archivio: tar -cf - /percorso/alla/mia_cartella | gzip > mio_archivio.tar.gz
	-p 				--> (preserve) conserva tutte le informazioni di protezione
							– (funziona pienamente solo per root, un utente standard quando ricrea i file estraendoli da un archivio è forzato a dargli la sua ownership)
	-v 				--> stampa i dettagli durante l’esecuzione
	-T <ELENCO> 	--> prende i nomi dei file da archiviare da ELENCO invece che come parametri sulla riga di comando
	-C <DIR> 		--> svolge tutte le operazioni come dopo cd DIR
	Esempi utili: 
	tar cvpf users.tar /home/* <-- creazione
	tar -C /newdisk -xvpf users.tar <-- estrazione
	tar cvpf - /home/* | tar -C /newdisk -xvpf - <-- pipeline

$ rsync [OPZIONI] SORGENTE DESTINAZIONE
--> versione evoluta di scp, per copiare file su un altro host.
		– SORGENTE = elenco di file e cartelle
		– DESTINAZIONE = cartella
	Copia via rete con protocollo nativo
		– da / verso host su cui gira il demone rsyncd
			rsync [USER@]HOST::SRCDIR DESTINAZIONE
			rsync SORGENTE [USER@]HOST::DESTDIR
	Copia via rete via SSH
		– no demone rsyncd richiesto
			rsync [USER@]HOST:SRCDIR DESTINAZIONE
			rsync SORGENTE [USER@]HOST:DESTDIR
	Opzioni utili:
		Come copiare
			-l / -L copia i link come link / come file puntato
			-p / -o / -g preserva i permessi, il proprietario, il gruppo
			-t / -a / -N preserva i ts di modifica / accesso / creazione
			-D preserva i file speciali
			-a = -rlptgoD
			-b backup (come? --backup-dir / --suffix )
		Cosa copiare
			-r ricorsivo
			-u salta i file che sono più nuovi a destinazione o che a parità di età hanno la stessa dimensione
			-c salta i file che a destinazione hanno lo stesso checksum
			--exclude specifica path da non includere nella copia

$ ip [ARGS]
-->  sostituisce ifconfig e route,controllo completo di tutti gli aspetti più avanzati (link layer, interfacce virtuali, tunnel, VXLAN, policy-based routing, ...)
		sottocomando address (a)
			– visualizzazione ip a
			– assegnazione ip a add <address>/<mask> dev <interface>
			– rimozione ip a del <address>/<mask> dev <interface>
		sottocomando route (r)
			– visualizzazione ip r
			– routing via gw ip r add <dst_net>/<mask> via <gw_addr>
			– routing via dev ip r add <dst_net>/<mask> dev <interface>
			– rimozione ip a del <address>/<mask>

$ ss [ARGS]
--> Verifica dello stato delle connessioni
	Opzioni utili:
		-t / -u	--> TCP/UDP only
		-l / -a	--> stato LISTEN (il default è ESTABLISHED) / ALL
		-n 		--> non risolvere gli indirizzi/porte in nomi simbolici
		-p 		--> mostra processi che usano la socket

$ tcpdump [ARGS]
--> intercettazione contenuto dei pacchetti

$ getent <db name> <keyword>
-->  permette di interrogare i database del name service switch (NSS)

$ host [ARGS]
--> tipicamente per conversioni IP ←→ nome
		– query di un nome: host www.unibo.it
		– query a un server specifico: host www.unibo.it 8.8.8.8

$ dig [ARGS]
--> ipicamente per ottenere informazioni legate a un dominio diverse da nomi host
		– conoscere i Mail eXchanger: dig mx example.com
		– conoscere i Name Server: dig ns example.com
		
$ ps [ARGS]
--> permette di ottenere informazioni sui processi. Disponibili diverse opzioni:
	- sezione PROCESS SELECTION BY LIST per listare processi secondo le loro proprietà,
	- sezione OUTPUT FORMAT CONTRO per specificare come formattare la lista prodotta,
	- sezione PROCESS STATE CODES spiega il significato della colonna STAT.

$ uptime [ARGS]
--> dà diverse informazioni circa: tempo attuale, da quanto tempo il sistema è in esecuzione, quanti users sono attualmente loggati e il carico del sistema negli ultimi 1, 5 e 15 minuti.
	Output tipo:
		15:40:05 up 21:19,  1 user,  load average: 0.44, 0.34, 0.23
	Nota: Load average = media, su 1/5/15 minuti, del numero di processi in stato R (running/runnable) o D (uninterruptible I/O). Non è % CPU, ma domanda di CPU/I/O rispetto ai core
	disponibili.

$ free [ARGS]
--> occupazione memoria. Alla cache si può rinunciare (con un impatto), infatti: available ≈ free + buff/cache

$ top [ARGS]
--> riassume interattivamente l'output di ps, uptime e free, quindi dà informazioni sui processi e le risorse usate.

$ vmstat [PERIODO] [ARGS]
--> uso di memoria, paging, I/O, trap. Se specificato PERIODO, numero intero, ripete l'operazione ogni PERIODO secondi.

$ iostat [ARGS] PERCORSO
--> statistiche su uso CPU e I/O. Utile soprattutto per valutare l'uso dei dispositivi di I/O.

$ df [ARGS]
--> mostra l’utilizzo dello spazio disco. Le righe sono formattate tipo:
	Filesystem 	1K-blocks 	Used 	Available 	Use% 	Mounted on
	udev 		101812 		0 	101812 		0% 	/dev

$ du [ARGS]
--> permette di calcolare lo spazio occupato dai file (in una directory). Senza opzioni particolari du riporta l’occupazione totale delle dir passate come argomento ed anche di tutte le 
    subdir in esse presenti. 
    -s riporta il summary, senza dettagli sulle subdir.
    
$ fuser [ARGS] [PATH]
--> permette di individuare quali processi stiano usando un file o un intero filesysyem.
    -m PATH	spcifica un inter ofilesystem (PATH) e restituisce tutti i processi che ne fanno uso.
    c current directory.
    e executable being run.
    f open file. f is omitted in default display mode.
    r root directory.
    m mmap'ed file or shared library.
    
$ lsof [ARGS]
--> lista di file aperti. Elenca tutti i file impegnati da tutti i processi.
    Nota: un file cancellato (unlink) dopo l'apertura sarà irreperibile sul filesystem, ma referenziato dal processo e quindi visibile a lsof.
